## Three role signature features (2026-10-18)

- Admin: polygon service areas, zone fee configuration, and a read-only what-if simulator for zone demand, estimated capacity, backlog, and fee revenue. The map uses a dedicated referrer-restricted `GOOGLE_MAPS_MAPS_JS_API_KEY`; browser code does not use the backend key.
- Dispatcher: 60-minute recovery recommendations and a booking/retry action. Courier booking claims the unique `dispatch_recovery_locks` row before contacting the provider. Confirmed provider order IDs release the reservation; ambiguous placement results retain both the lock and quotation so a follow-up click cannot duplicate a booking. Pending hold requests can be marked accepted/rejected; those are dispatch decisions, not automatic courier pauses.
- Customer: paid-or-later orders can issue, rotate, or revoke a seven-day Control Pass, stored as a token hash and separate from the courier tracking URL. Public token reads are narrowly projected and rate-limited; writes allow an order-specific drop-off instruction update or a pending hold request. Instruction writes are accepted before pickup, and hold requests await dispatch review.
- Verification: `tests/test_t9_signature_features.php` and `tests/test_t8_courier_recovery.php` pass. T6 and T7 pass. Syntax checks passed for the changed controllers, services, views, migration, and tests. The historical T2/T5 dispatch-board HTTP requests returned 500, then attributed to missing migration-003 snapshot columns; a later read-only metadata probe found those columns present, but dispatch HTTP has not been rerun. Migration 004 and other DB state were not changed during this follow-up. The historical schema/seed result reported four customers instead of the expected three due to repeated local test data. No database migrations were applied during this follow-up.
